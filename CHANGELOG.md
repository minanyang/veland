# Changelog

## 0.1.0 — unreleased

- The loop: `/cutter:open` (draft a GitHub issue, classified with the repo's labels or issue types; created on approval), `/cutter:work` (plan → worktree → implement → commit → red-proof → verify + cold review → fix → one cold review of the fix commits) and `/cutter:close` (rebase → verify → `pr` / `pr-merge` / `local`, each landing the branch as one squash commit; `local` tickets build on the unpushed local base; fills the repo's PR template; checks `gh` / `glab` before pushing; cleans up squash-merged branches, local and remote; fast-forwards the main checkout's base after a merged PR when it is on the base and git allows it, keeping unrelated uncommitted changes).
- The grill: before drafting, `/cutter:open` (product questions) and `/cutter:work` (technical questions) walk the open decisions with you in rounds, a recommended answer per question and depth scaled to the ticket, from one shared `references/grill.md`; drafts and plans list what was not settled under `## Assumptions`. On a GitHub ticket, `/cutter:work` posts the product answers to the issue as one comment.
- Issues: `.github/ISSUE_TEMPLATE/` bug and feature forms (blank issues off); `/cutter:open` drafts in a repo's form fields, titles by problem or need, numbers criteria, cites evidence for its Context and maps a multi-ticket request's goals to tickets first; `cutter-land issue` refuses drafts with missing required sections, unnumbered criteria, two checkboxes on a line or a phrase from `references/banned-phrases.txt`, and deletes the draft once the issue exists. Creating an issue and posting the planning comment always ask for permission.
- The flow skills and review agents check a claim before replying rather than reporting it unverified.
- `/cutter:open`, `/cutter:work` and `/cutter:close` reply result first and say each fact once, with security warnings, irreversible actions, questions and persisted text exempt; `/cutter:work` ends with a fixed-shape report, and a draft or plan shown for approval is shown once, verbatim, with its path.
- Tickets from a description or a GitHub issue (`gh`).
- Scripts: `cutter-land` (`pr`, `issue` and `comment` build the PR/MR, issue and issue-comment commands from files under `.cutter/`), `cutter-worktree`, `cutter-verify` (runs the gates the ticket's worktree declares, listing changes against the base's; on cutter itself, lists the worktree's `bin/` and `scripts/` files that differ from the running copy), `cutter-red-proof`, `cutter-review-packet` (`--fixes` for the commits since the last review, quoting the last round of `review.md`; both packets leave agent memory out of the diff and list the commits that touch it), `cutter-ticket` (reads issues of origin's repo only; `issue-types` lists its issue types for `/cutter:open`).
- Agent memory written during `/cutter:work` — in the main checkout or the worktree — is committed on the ticket's branch before the report (`cutter-worktree memory`), leaving the main checkout clean; `cutter-verify` and `cutter-red-proof` ignore memory an agent writes into the worktree while they run.
- `redProof.command` / `redProof.tests` let `cutter-red-proof` run any test runner; `preReviewGates` run before `cutter-review-packet` builds, so no reviewer reads a diff that fails the quick gates.
- Plans and evidence: `/cutter:work` plans number their criteria and carry `## Readers`, `## Tool behaviour relied on`, `## Overlap` and a `## Tests` table, checked by `cutter-plan-check` before you see them; a plan binding more than three files is read cold by an `Explore` agent first. `cutter-review-packet` lists planned test cases missing from the diff and removed terms still in the tree as findings, and requires a security review when the diff touches a granted script, a skill's or agent's frontmatter or a hook, or a file such a script or hook loads. A problem the change causes is fixed in the ticket, anything else is asked; `.cutter/<id>/evidence.md` tracks each criterion as `met`, `deferred` or `asked`, and a Stop hook keeps the session from ending while one is unaccounted for or when a flow or reviewer reply calls something unverified.
- Agents: `frontend-engineer`, `backend-engineer`, `devops-engineer`, `qa-engineer`, `code-reviewer` (do-not-report list, confidence ≥ 80), `security-reviewer`.
- Skills: `commit`, `code-review`, `code-review-branch`.
- Hooks: guard against destructive Bash commands; context gate for the flow skills; Stop gate on criteria evidence and unverified claims.
- Project config in `.claude/cutter.json`; ticket files in `.cutter/<id>/`, kept out of git via `.git/info/exclude`.
- CI: `.github/workflows/ci.yml` runs the project's gates (`scripts/ci-gates.sh`) on Linux and macOS for pushes to `main` and pull requests; `cutter-land merge` on GitHub refuses a PR whose head is not pushed or whose checks are not green. In `pr-merge` mode `/cutter:close` waits for pending checks in the background (`cutter-land wait`, up to 30 minutes) and then merges by itself; `merge` exits 3 when checks are only pending and 4 when `origin/<base>` moved since the rebase, which sends close back to rebase (at most 3 rounds).
- Grant hook: the Bash grants of `/cutter:open`, `/cutter:work` and `/cutter:close` hold for the whole session in which you typed the skill — in a background wake-up, a same-session approval turn and a `--resume` turn — so close merges after `cutter-land wait` and work implements after "approved, go" without a prompt. Grants are snapshotted when the skill is typed into `${CLAUDE_PLUGIN_DATA}/sessions/`, and allow only a single command, outside subagents, once the session's transcript shows you typed the skill (a scheduled prompt naming it grants nothing).
- Self-tests for the guard, the context gate, the Stop gate and the scripts.
